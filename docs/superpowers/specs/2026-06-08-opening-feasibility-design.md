# 开题可行性设计

## 范围

本设计用于确定学位论文的稳定开题方向：

**面向工业设备异步多传感器的概率状态预测与风险评估方法研究**

当前工作应首先保证开题可行性，再指导实验结果优化。开题报告以 MetroPT-3 和 C-MAPSS 作为主数据集。Tennessee Eastman Process（TEP）作为扩展或条件验证数据集描述，不在开题阶段承诺为必须完成的主实验。

当前仓库已经包含：

- KAFNet-ProFITi 融合设计文档。
- 统一对比实验协议。
- 可运行的 KAF-ProFITi 原型。
- MetroPT-3 和 C-MAPSS 数据适配器。
- `kaf_profiti_joint` 在 MetroPT-3 和 C-MAPSS FD001 上的初步冒烟实验结果。

当前结果尚不能作为论文级证据，因为它们只覆盖一个最终模型、一个随机种子、较短窗口和很短训练。它们应被描述为原型可行性证据，而不是已完成的对比实验结果。

## 推荐路线

采用 **开题稳健路线**：

1. 稳定开题报告的问题定义、章节结构、创新点、可行性分析和文献计划。
2. 只承诺开题后现实可完成的实验。
3. 将现有结果视为软件原型可运行的证明。
4. 在开题方向固定后，优先补齐真实基线、消融实验、三 seed 统计和缺失率鲁棒性。

该路线优于结果优先路线，因为当前基线、消融、风险评分和多 seed 证据尚不完整。它也优于完整论文路线，因为 40 篇核验文献和完整实验矩阵会过早扩大范围。

## 论文定位

论文不应被表述为单纯故障检测。建议采用两级任务定义：

1. **未来概率状态预测**：在异步和缺失观测条件下，预测多个传感器未来状态的联合分布。
2. **基于预测分布的风险评估**：将预测样本或预测区间转化为可解释的风险分数、预警概率、校准指标，并在标签允许时计算提前预警指标。

这种表述可以避免在故障标签稀疏或人工构造的数据集上过度声称。它也使 KAFNet-ProFITi 融合成为核心技术贡献，而不是简单模型串联。

## 数据集承诺

主数据集：

- **MetroPT-3**：主要工业空气压缩机数据集，用于未来传感器状态预测和基于故障报告的预警窗口评估。
- **C-MAPSS FD001**：主要退化验证数据集，用于传感器状态预测和基于 RUL 阈值的风险验证。

可选扩展：

- **C-MAPSS FD002-FD004**：在 FD001 稳定后扩展。
- **TEP**：作为过程工业扩展讨论。除非故障协议、内存和运行时间问题得到解决，否则完整 faulty run 实验应作为未来或条件工作处理。

## 开题报告结构

使用本地 `开题参考/开题报告.docx` 作为结构模板，但内容改为工业异步传感器预测方向。

推荐章节：

1. **选题背景、国内外研究现状及述评**
   - 工业预测性维护与设备状态预测。
   - 面向传感器系统的多元时间序列预测。
   - 不规则、异步和缺失时间序列建模。
   - 概率预测与不确定性量化。
   - 风险评估、校准和提前预警。
   - 述评应收束到三个不足：规则采样假设较强、点预测难以表达不确定性、风险评估缺少概率校准。

2. **研究内容和论文结构**
   - 第 3 章：统一工业数据协议与异步缺失构造。
   - 第 4 章：KAFNet-ProFITi 联合概率状态预测。
   - 第 5 章：风险评估、缺失鲁棒性、多 seed 统计和结果分析。
   - 第 6 章：总结与展望。

3. **创新之处**
   - 面向工业异步多传感器的工况感知规整表示。
   - 查询条件化的 KAFNet-ProFITi 联合 flow 概率状态预测。
   - 面向工业运维的基于分布样本的风险评分与鲁棒评估协议。

4. **可行性分析与进度计划**
   - 已有基础：原型模型、数据适配器、结果目录格式和冒烟实验指标。
   - 剩余工作：真实基线、消融、多 seed 评估、鲁棒性扫描、风险标签、核验文献和开题报告撰写。

5. **研究方法、重点难点**
   - 研究方法：文献调研、模型构建、受控对比实验、消融实验、鲁棒性评估、校准分析。
   - 关键难点：公平实验协议、概率指标可比性、真实异步缺失构造、风险标签定义、联合 flow 训练稳定性和可信多 seed 统计。

## 第 4 章和第 5 章创新映射

`开题参考/论文.docx` 中的参考论文采用两个方法章节，每章都包含动机、方法模块、参数优化、消融、对比和泛化验证。该写法可在写作结构层面复用，但不能复制其技术内容。

推荐映射：

- **第 4 章：KAFNet-ProFITi 联合概率状态预测**
  - 动机：点预测和重插值模型难以表达异步传感器观测下的未来联合不确定性。
  - 模块：IndustrialEventCollator、KAFNetEncoder、QueryConditionAdapter、ProFITiFlowHead。
  - 实验：主预测对比、概率指标、模型消融、参数敏感性。

- **第 5 章：风险评估与鲁棒性验证**
  - 动机：工业部署需要校准后的预警风险，而不仅是数值预测误差。
  - 模块：阈值/风险标签构造、基于样本的风险评分、校准评估、缺失鲁棒性协议。
  - 实验：风险预测、可靠性/ECE、缺失率扫描、三 seed 统计对比、选择性可视化分析。

## 最小真实证据矩阵

开题报告不应承诺原始 12 模型矩阵会立即全部完成。应使用分阶段矩阵。

### 最小主矩阵

| 实验 | 数据集 | 模型 | 随机种子 | 指标 |
|---|---|---|---|---|
| 主预测 | MetroPT-3, C-MAPSS FD001 | TCN-Gaussian, GRU-D, ProFITi, KAFNet, KAFNet-Gaussian, KAF-ProFITi Joint | 2026, 2027, 2028 | MAE, RMSE, NLL, CRPS, PICP |
| 消融 | MetroPT-3, C-MAPSS FD001 | KAFNet, Gaussian Head, Marginal Flow, Joint Flow, w/o context | 2026, 2027, 2028 | MAE, RMSE, NLL, CRPS, ECE |
| 缺失鲁棒性 | MetroPT-3, C-MAPSS FD001 | TCN-Gaussian, GRU-D, ProFITi, KAF-ProFITi Joint | 2026, 2027, 2028 | 缺失率 0, 0.1, 0.3, 0.5, 0.7；MAE, NLL, PICP |
| 风险评估 | MetroPT-3, C-MAPSS FD001 | Joint Flow 加可进行概率输出的基线 | 2026, 2027, 2028 | AUROC, AUPRC, F1, ECE, 标签支持时计算 Lead Time |

### 结果优化优先级

1. 实现最接近最终模型的消融：`KAFNet-Gaussian`、`KAF-ProFITi Marginal Flow`、`KAF-ProFITi Joint Flow` 和 `w/o context`。
2. 加入真实基线：至少包括 `TCN-Gaussian`、`GRU-D` 和 `ProFITi`。
3. 运行三个随机种子并报告 `mean ± std`。
4. 加入缺失率鲁棒性扫描。
5. 将当前冒烟实验风险公式改进为基于阈值或标签的风险定义。

## 当前证据边界

`code/results/metrics` 中现有指标只能描述为冒烟实验结果：

- 只覆盖 `kaf_profiti_joint`。
- 只覆盖 MetroPT-3 和 C-MAPSS FD001。
- 只使用一个随机种子 `2026`。
- 使用短窗口，已保存指标中为 `history=12` 和 `horizon=3`。
- 训练设置很短。
- 风险指标不完整，当前风险评分还不足以支撑论文级工业预警结论。

开题报告措辞应表述为：已经建立原型和统一结果保存框架，完整对比实验已规划并将在后续补齐。

## 文献核验计划

开题报告需要至少 40 篇真实参考文献，其中英文论文至少 20 篇，中文论文至少 10 篇，并尽量满足用户要求的 2022-2026 年范围。

不要编造文献。正式撰写参考文献前，应先建立核验表。

创建类似 `references_verified.csv` 的文件，包含以下字段：

| 字段 | 含义 |
|---|---|
| language | English 或 Chinese |
| year | 2022-2026 |
| title | 论文标题 |
| authors | 作者 |
| venue | 期刊或会议 |
| topic | irregular TS、probabilistic forecasting、predictive maintenance、RUL、calibration、missing data、industrial risk 等 |
| url | DOI、出版社页面、arXiv、CNKI、万方、期刊页或其他权威链接 |
| used_in | 开题报告对应小节 |

目标收集数量：

- 英文：至少 22 篇核验条目。
- 中文：至少 12 篇核验条目。
- 总数：40-45 篇核验条目，留出替换余量。

所有链接必须在执行阶段检查。最终报告只能引用通过年份、真实性和链接检查的条目。

## 仓库上传与变更治理

正式目标仓库为：

<https://github.com/PY0909/KAFNet-ProFITi.git>

该仓库应被视为可复现研究资产，而不只是代码堆放处。上传规范记录在 `docs/repository-governance.md`。

治理要求：

1. 跟踪源代码、实验配置、指标、表格、图、论文草稿、核验文献和设计文档。
2. 不通过普通 Git 上传原始数据、模型检查点、预测数组、Python 缓存、本地环境或本地密钥。
3. 每次有意义的改动都记录在 `CHANGELOG.md`。
4. 结果文件必须可追溯到数据集、模型、随机种子、缺失率设置、划分规则和配置。
5. 在整理成规范仓库前，将第三方代码规范化到明确标注的文件夹或子模块中。
6. 使用 `.gitignore` 防止误传大型生成文件。

推荐文件类别：

| 文件类型 | 示例 | 策略 |
|---|---|---|
| 代码 | `code/kaf_profiti/**/*.py`、测试、脚本 | 跟踪 |
| 配置 | YAML 实验配置 | 跟踪 |
| 指标和表格 | JSON 指标、CSV 表格 | 核验后跟踪 |
| 数据清单 | 数据来源和预处理说明 | 跟踪 |
| 原始数据 | 下载的 CSV/TXT/RData/PDF 数据文件 | 不跟踪 |
| 模型产物 | 检查点和预测数组 | 不通过普通 Git 跟踪 |
| 论文资产 | 开题报告草稿、图、核验文献 | 跟踪 |
| 缓存 | `__pycache__`、`.pytest_cache`、`.DS_Store` | 不跟踪 |

## 成功标准

该设计成功的标志是：

1. 形成一份清楚区分已完成原型工作和计划中完整实验的开题报告草稿。
2. 论文结构中每个创新点都有对应的方法章节和实验组。
3. 实验矩阵以 MetroPT-3 和 C-MAPSS 为中心，TEP 被稳妥限定为扩展工作。
4. 文献流程满足 40 篇论文、英文/中文、2022-2026、真实链接的要求。
5. 仓库上传流程能区分可跟踪研究资产和原始/生成大型文件，并记录每次有意义改动。
6. 后续实施计划优先推进消融、真实基线、多 seed 评估和风险评分修正。

## 本设计范围之外

- 撰写完整开题报告。
- 实现新基线或消融。
- 运行长实验。
- 产出最终核验的 40 篇参考文献。
- 声称最终实验优于所有基线。

这些事项应在用户 review 本设计后进入后续实施计划。
